# Formula OCR Optimized Model Packaging Test

Date: 2026-10-17

## Assets

The original model was preserved before packaging:

| `pp_formulanet_plus_m.optimized.onnx` | 593,916,167 | `6e509ec4b7cda604dc9bf80a876ae6494693deea4c7f4157a4dc0eba0ebda745` |

The optimized file is generated by
`tools/hoist_formula_encoder_projection.py`. The generator now removes the
dead Loop-local copies of the hoisted projection weights, so the packaged
file is effectively the same size as the source model. It is stored beside
the default asset under `models/formula/recognition/onnx/`.

## Correctness gate

Both models were run with the Rust release `formula_eval` binary, ORT 1.28,
CPUExecutionProvider, automatic intra-op 14/inter-op 1, and the pinned
64-image manifest.

| --- | ---: | ---: |
| Scored | 64 | 64 |
| Exact matches | 19 | 19 |
| Normalized matches | 19 | 19 |
| Mean CER | 0.0673319232 | 0.0673319232 |
| Pipeline failures | 0 | 0 |
| Truncated | 0 | 0 |
| EOS-truncated token/LaTeX differences | - | 0/64 vs original |

The optimized model also passed the 501-image set with the same summary as the
original: exact 190, normalized 194, mean CER `0.0796678406`, one truncated
sample, and zero pipeline failures. A direct record comparison found no token,
EOS, or decoded LaTeX differences.

## Performance gate

The 64-image independent single-image run measured **1,077.5 ms/image** for
the optimized model. The established three-run original baseline is **1,119.7
ms/image**. This is a single additional run and is reported as directional
evidence, not as a new stable single-image estimate.

For batch=8 over 501 images, two runs of the optimized model measured 444.4 s
and 458.6 s. The current original-model rerun measured 501.8 s under the same
conditions. These runs show a positive 8.6% to 11.4% difference on the current
machine, but are slower than the earlier alternating candidate estimate of
289.4 s. The latter discrepancy demonstrates substantial machine-load
variance; the optimized model is not claimed to deliver a fixed 20% gain.

## Adoption decision

The optimized model passes correctness and has positive measured direction, so
it is packaged as an explicit opt-in asset. The default model path and download
registry remain unchanged because the optimized file has not been uploaded to
the declared model source URL. Changing the registry SHA-256 now would make a
clean installation download the original file and fail verification.

To make this the default distribution asset, publish
`pp_formulanet_plus_m.optimized.onnx` (or rename it at the hosting layer), then
update `assets/default_models.yaml`, `models/serve/manifest.json`, and the
registry tests with the new SHA-256 and byte count. Until that happens,
production behavior continues to use the backed-up original model.
